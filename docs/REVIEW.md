# Review of the original repo: what was wrong and what changed

| # | Severity | Original | Why it matters | Now |
|---|---|---|---|---|
| 1 | Critical | DB password written in `terraform/main.tf`, `Jenkinsfile`, `README.md` and `application.properties` | Anyone with repo access (or history) has the production DB password; the Jenkinsfile even `sed`-injected it into a file baked into the image | RDS generates the password (`manage_master_user_password`), stored in Secrets Manager; read at deploy time into a Kubernetes Secret |
| 2 | Critical | RDS `publicly_accessible = true` and security group `3306` open to `0.0.0.0/0` | The database is reachable from the whole internet | Private database subnets, no public access, only the EKS node security group can connect |
| 3 | High | Static AWS access keys in Jenkins (`aws-cred`) and `aws configure` on the host | Long-lived keys with broad rights; a leak = account compromise | No keys anywhere. Agent uses an IAM instance role with ~5 scoped permissions |
| 4 | High | Terraform ran inside the pipeline with `apply --auto-approve` and local state in the Jenkins workspace | Unreviewed infra changes on every build; wiping the workspace orphans the whole stack (README's destroy relied on it) | Remote encrypted S3 state with locking; plan is reviewed and applied by an engineer; Jenkins cannot change infrastructure |
| 5 | High | Default VPC, public subnets for nodes and RDS, EKS API open to the world | No network isolation | Dedicated VPC: public (ALB/NAT), private (nodes/CI), database subnets; EKS API restricted to your CIDR + private endpoint |
| 6 | High | Backend `Service type: LoadBalancer` (public) and `allowedOriginPatterns("*")` with credentials | API exposed directly; any website could call it with cookies | Backend is ClusterIP; single ALB with `/api` and `/` paths; CORS off by default and configurable |
| 7 | High | Images pushed to Docker Hub, tags `backend-<build>`, containers run as root, JDK + Maven in the runtime image, `node:25` + apache | Larger attack surface, no registry scanning, non-LTS Node | ECR (immutable tags, scan on push, lifecycle policy), multi-stage builds, JRE-only non-root backend, unprivileged nginx |
| 8 | Medium | DevSecOps only in a separate, mis-named file (`frontend/Sonar-Trivy/backend-jenkinsfile.grrovy`): quality gate `abortPipeline: false`, Trivy output to a file after pushing, no exit code | Scans never blocked a release and ran after publishing | Scans in the main pipeline before push: Gitleaks, SonarQube gate (blocking), Trivy fs/config/image (fail on HIGH/CRITICAL), manual approval, auto-rollback |
| 9 | Medium | Frontend built after reading the backend LoadBalancer DNS (`sleep 30` + `sed` on `.env`) | Race condition; breaks when the LB changes; needs a rebuild per environment | `VITE_API_URL=/api` (same host); no ordering hack |
| 10 | Medium | Jenkinsfile credential IDs `aws-cred`, `docker-cred`, `rds-cred` vs README `aws-creds`, `dockerhub-cred`, `rds-creds` | The README instructions produce a pipeline that fails | Only one credential remains (`sonar-token`); documented consistently |
| 11 | Medium | Pipeline created table `students`, but the JPA entity `User` maps to table `user` | The created table was never used; DB name differed too (`easycruddb` vs `student_db`) | RDS creates `student_db`; Hibernate manages the table |
| 12 | Medium | `mvn clean package` inside the Docker build runs `contextLoads`, which needs a live DB | Build breaks once the DB is private | Image build skips tests; tests run in the pipeline against in-memory H2 |
| 13 | Medium | `sonar-maven-plugin` declared as a compile *dependency* | Packaged into the application jar | Removed |
| 14 | Medium | `agent any`: builds ran on the Jenkins controller; credentials interpolated into double-quoted Groovy strings | Untrusted build code on the controller; secrets can leak into logs | Controller has 0 executors, builds run on a labelled agent; no secrets interpolated |
| 15 | Low | K8s: default namespace, no probes, resources, securityContext, PDB, HPA, network policy; `forntend-svc` typo vs README `frontend-svc`; single replica and single node | No resilience or isolation | Namespace with Pod Security `restricted`, 2+ replicas, probes, resources, PDB, HPA, default-deny NetworkPolicy |
| 16 | Low | README claimed Terraform creates a VPC/IGW and "production-grade" | Documentation did not match the code | README rewritten to match |
